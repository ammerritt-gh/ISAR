# Documentation inventory and disposition

> **Lifecycle:** Current
> **Authority:** canonical for what every documentation file *is* and who maintains it
> **Provenance:** hand-written
> **Verified against code revision:** `389f571` (2026-07-25)

This is the register of the documentation tree. It exists because "keep the maintained documents
up to date" was previously undefined — nobody could say which of the Markdown files in this
repository were contracts, which were evidence, and which were dead.

Every `.md` file in the repository appears exactly once below — as its own row, or, for
generator-owned outputs, under the glob that covers it in *Generated — exempt from lifecycle
banners*. **That is enforced**: `tests/docs/test_doc_drift.py` parses the Path column of every
register table and asserts a one-to-one mapping against the non-exempt half of
`git ls-files '*.md'` — a tracked file missing from the register fails, a path registered twice
fails, and a row naming a file that does not exist fails. The tombstone table is parsed the same
way, so a deleted file cannot quietly return. Banner and provenance fields are checked separately,
per file.

**Every path below is repository-relative and complete.** Section headings group the register for
a human reader; they are not path prefixes, because a heading-relative path is exactly the
ambiguity that lets a row silently resolve to a file that does not exist.

## The three fields

They are orthogonal, and conflating them is what produced the mess this register cleans up.

**Lifecycle** — one of four, and nothing else:

| Value | Meaning |
|---|---|
| `Current` | Describes present behaviour. Maintained with the code. May be cited as authority. |
| `Active plan` | Approved work not yet fully implemented. Needs an owner and exit criteria. |
| `Historical evidence` | Records what happened. Never normative. Points forward to the current contract. |
| `Archived` | Useful implementation history, no longer maintained. Names its replacement. |

**Authority** — *optional*. Only documents that are the single canonical source for a topic
declare it. Explanatory, rationale, and historical documents legitimately have none, and forcing
them to claim one invents authority that does not exist.

**Provenance** — `hand-written` or `generated by <command>`. Independent of lifecycle: a
generated file can be current, historical, or archived. Generated files are exempt from the
lifecycle-banner requirement because the generator, not a human, owns their text.

## Rules this register enforces

1. A `Current` document may not take a `Historical evidence` or `Archived` document as its
   **normative source**. Citing one for rationale or provenance is fine and common — the
   distinction is whether removing the citation would leave a claim unsupported.
2. Campaign records are evidence, not contract (`DECISIONS.md` D3).
3. A handoff is temporary. Once its receiving work starts it converts to an active plan, folds
   into a canonical reference, or archives. There is no long-lived handoffs directory.
4. An execution plan leaves the active tree when its work lands.
5. `Active plan` requires an owner and exit criteria; without them it is not a plan.

Rules 2–4 and the *normative source* half of rule 1 are review items — no checker can judge
whether a citation is normative. What **is** enforced by `tests/docs/test_doc_drift.py`: the
one-to-one register mapping above; every tracked `.md` declares a valid lifecycle and provenance;
every `Active plan` declares an owner and exit criteria (rule 5); every relative link resolves
(case-sensitively, so a GitHub-only breakage fails locally); a tombstoned file is absent from the
tree; a maintained document that names a deleted file says in the same paragraph that it is gone;
a maintained document contains none of the phrases that were corrected once already; any command
list marked `<!-- isar-commands: exhaustive -->` matches `isar.cli.main.build_parser()` exactly;
`DECISION_INDEX.md` matches a fresh render from the ledger; and every file in the `docs/assets/`
bundle matches the hash recorded for it in `MANIFEST.json`.

**There is deliberately no inbound-reference count.** An earlier version of this register carried
one, labelled machine-computed, with no generator behind it and no test keeping it honest; the
first deletion pass invalidated every number at once. A count nobody recomputes is worse than no
count. Where an inbound reference actually matters it is named explicitly as a deletion blocker,
and verified by `git grep` at deletion time rather than by bookkeeping.
